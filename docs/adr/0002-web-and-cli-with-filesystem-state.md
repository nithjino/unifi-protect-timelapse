# Web and CLI only, with the filesystem as export state

Version 3 keeps the web dashboard and CLI and removes the Qt, macOS, and Windows apps, because the web dashboard already works on every platform and three desktop apps cost more than the rest of the project combined. A Daily Automation now stores only its definition and `next_day`; whether an Export Artifact exists is answered by the output directory, so an interrupted day is run again and existing artifacts are skipped. We rejected keeping durable batch and job records because no recovery path needed them that the deterministic output paths did not already provide.

Each runtime owns one `ProtectClients` object, passed explicitly to the service functions, with one client per credential set. This replaces the context-variable pool, which never reached web request handlers, and the cross-process file locks, which only mattered while desktop apps and their backends shared a session. uiprotect already merges concurrent logins on one client and reloads the saved session after a restart. A CLI run alongside the web server now coordinates with it only through that saved session, so the two can each use their full slots. Exports and thumbnails hold separate per-console slots, so a preview never waits for a multi-hour export.

The export folder stays the source of truth for storage. A daily export pauses its automation once the folder reaches the quota, because its size is unknown beforehand and reserving the download limit would stop it about 18 days early. Retention is off by default because deletion is irreversible. When set, it covers every MP4 in the folder by file age, since jobs trimmed from the history can no longer say which exports were manual. Those trimmed exports are listed directly from the folder as Older Exports, with no stored index.

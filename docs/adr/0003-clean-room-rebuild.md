# Clean-room rebuild around one job and one automation record

Version 4 rebuilds the Python code from a written specification, without reading the version 3 implementation, to test whether the same product needs that much code. One `Job` record serves the queue, the dashboard and the history file, and one `Automation` record with pure transitions serves the registry, the runner and the views; all state changes happen between `await`s on one event loop, so no locks, callbacks or copies between parallel structures are needed. One `Protect` object per console owns the uiprotect client, its retry policy and its export and thumbnail slots, and the dashboard polls instead of streaming events. We rejected keeping server-sent events, a row per export attempt, and blocking automation removal until running exports finish, because each needed machinery that the simpler behaviour does not.
